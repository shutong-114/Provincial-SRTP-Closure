1 项目目标与问题定义

本项目构建了一个"可切换算法 + 可切换任务模式"的 TSP 可视化实验平台，核心目标是：

  1. 在统一工程框架下比较不同求解算法（SA、GA）的行为差异。
  2. 支持从经典最短路回路任务平滑扩展到带时间约束与优先级的任务调度问题。
  3. 通过动画化过程展示，让优化"结果"与"搜索过程"都可观察、可解释、可复现。

平台面向二维平面任务点，当前采用欧氏距离作为基础移动成本。

2 基本代码思路（核心实现逻辑）

2.1 总体架构思路

系统按"配置层 → 目标函数层 → 求解器层 → 可视化层 → 数据层"分层组织：

  • config.py：统一管理可切换参数（solver / task / route mode、超参数、惩罚权重）。
  • objectives/：封装 classic 与 time_window 两类代价函数。
  • solvers/：实现 SA 与 GA，输出统一的 SolverResult 与 HistoryFrame。
  • visualization/：负责图绘制与动画播放。
  • data/：提供可运行样例任务集。

这样做的价值是：算法切换、任务切换、展示切换彼此解耦，便于快速实验与后续扩展。

2.2 配置驱动的模式切换

平台通过 ExperimentConfig 控制行为，主要切换参数包括：

  • solver_type：SA | GA
  • task_mode：classic | time_window
  • route_mode：fixed_depot（当前默认）
  • start_node_id：默认 1（固定起终点）

配置驱动避免了硬编码分支，提升了实验可重复性和参数可追踪性。

2.3 目标函数设计思路

classic 模式

目标是最小化回路总距离：

J = route_length

time_window 模式

目标函数采用加权和：

J = α × route_length + β × late_penalty + γ × early_penalty

其中：

  • late_penalty：采用分段二次惩罚，并乘以 2^priority 实现优先级放大。
  • early_penalty：采用轻微线性惩罚，避免过度提前完成。

设计原则是"晚到强惩罚、提前轻惩罚"，使系统在不可避免违约时更倾向保护高优先级任务。

2.4 求解器设计思路

SA（模拟退火）

  • 邻域操作：swap、2-opt、segment reverse。
  • 退火接受机制：允许以概率接受劣解，减少陷入局部最优。
  • 每轮记录历史帧，支持动画播放。

GA（遗传算法）

  • 编码：节点访问序列。
  • 流程：随机种群 → 锦标赛选择 → OX 交叉 → 变异 → 精英保留。
  • 适应度：fitness = 1 / (cost + 1e-6)。
  • 每代记录历史帧，支持动画播放。

2.5 固定起终点（depot）实现思路

当前默认 route_mode=fixed_depot，start_node_id=1。
实现上采用"内部路径 + depot 拼接"策略：

  1. 求解器仅优化 depot 之外的内部序列。
  2. 评估前统一构造完整路径 [start_node_id, *inner_route]。
  3. 闭环回路仍由目标函数层统一处理。

这样既保持了固定起终点约束，又保留了 SA/GA 既有优化能力。

2.6 可视化与可解释性思路

  • 使用 networkx + matplotlib 绘制 circle-edge 图。
  • 边上显示欧氏距离权重。
  • 当前最优路径高亮。
  • FuncAnimation 播放搜索过程（SA 按迭代，GA 按代）。
  • 信息面板展示：模式、代价、迭代计数、时间窗指标。

此外，展示层将求解器内部"索引路径"映射为任务 task.id 展示，提升了输出可读性和用户理解一致性。

4 额外贡献思路（可用于答辩/创新点）

以下内容是基于当前平台可直接推进的"额外贡献方向"，可作为课程创新点或论文后续工作：

🔒 贡献方向 A：约束处理增强
  1. 硬约束版时间窗：在 SA/GA 中加入可行性修复（repair operator），优先生成可行解。
  2. 动态权重策略：随迭代自适应调整 α/β/γ，前期探索、后期收敛。
  3. 多目标优化：将"路径长度、晚到任务数、最大延迟"做 Pareto 前沿分析。
价值：从"软约束优化"升级为更工程化的"可行性优先 + 多目标权衡"
⚡ 贡献方向 B：算法性能提升
  1. SA 混合邻域调度：根据阶段温度自适应选择邻域算子。
  2. GA 局部搜索融合：对精英个体做轻量 2-opt 作为 memetic algorithm。
  3. 参数自动调优：用网格搜索或贝叶斯优化进行离线超参数标定。
价值：同等时间预算下获得更优解、更稳定收敛曲线
📊 贡献方向 C：实验与评估体系建设
  1. 增加随机任务生成器，按规模/约束强度分层评测。
  2. 固定随机种子批量跑实验，输出统计结果（均值、方差、箱线图）。
  3. 建立标准指标：总成本、路长、晚到率、最大延迟、收敛速度、计算时间。
价值：从"演示系统"升级为"可复现实验平台"
🌐 贡献方向 D：场景扩展
  1. mTSP：多机器人协同访问任务点。
  2. VRPTW：引入容量约束与时间窗，贴近物流调度。
  3. 动态任务插入：运行中新增任务并增量重规划。
  4. 局部路径层接入 A*/Dijkstra：用于障碍地图和真实路网。
价值：把课程级平台平滑升级到更贴近工业问题的调度框架
🖥️ 贡献方向 E：可视化与交互增强
  1. 参数面板：运行中切换算法与权重。
  2. 多图联动：同时展示代价曲线、延迟分布、任务甘特视图。
  3. 回放控制：暂停、逐帧、倍速、关键帧跳转。
  4. 结果导出：CSV / JSON / GIF / MP4。
价值：增强教学演示、实验分析与项目展示效果
5 风险与改进建议
  • ⚠️ start_node_id 当前按任务列表索引解释，而非任务 id 字段；后续若接入外部数据，建议统一为按 Task.id 指定 depot。
  • ⚠️ 大规模任务下，matplotlib 动画性能可能受限；可考虑抽样显示或迁移到更高性能渲染方案。
  • ⚠️ 当前算法属于启发式近似，不保证全局最优；报告中应明确"实验求解"定位与适用范围。
6 结论

本项目已完成一个结构清晰、可切换、可视化、可扩展的 TSP 实验平台。

其核心价值在于：把"算法实现、目标建模、过程可视化、实验对比"整合到统一框架中， 并通过固定起终点、时间窗惩罚和测试保障提升了工程完整性。

在此基础上，平台可进一步演化为面向 mTSP、VRPTW 与动态调度的研究原型，具备较好的继续开发潜力。
